# site-prompt — генератор уникальных промптов для сайтов

Пользователь даёт **тему** сайта → скилл выдаёт готовый **промпт** для создания сайта под неё. Промпт описывает идею, бизнес-модель, структуру, блоки, визуал, наполнение. Сам сайт потом создаётся из этого промпта (в OpenDesign или любым генератором).

**Ключевое требование: абсолютная уникальность.** Два промпта (даже на одну тему) не должны давать похожие сайты. Уникальность обеспечивается движком `draw_axes.py`: он вытягивает неповторяющуюся комбинацию дизайн-осей из больших банков (`references/banks.yaml`) и ведёт журнал уже использованных комбинаций (`.history/fingerprints.jsonl`), избегая повторов и недавних значений.

**Сайты = PHP-расширение, но это обычный HTML/CSS/JS.** Никакого React/Vue/Next/SPA/сборщиков.

## Аргументы

- **Тема** (обязательно) — отрасль/ниша сайта, свободным текстом. Напр. «автосервис», «студия керамики», «клининг для офисов», «школа английского».
- **--geo `<CC>`** (опц.) — целевая гео/страна (влияет на формат телефона, язык контента, юр-страницы вроде Imprint для DE/AT).
- **--lang `<code>`** (опц.) — язык контента сайта, если отличается от гео-дефолта.
- **--workspace `<name>`** (опц.) — куда сохранить md-файл промпта (по умолчанию `yp`).

Ниша должна быть НЕ лицензируемой (без мед/финанс/юр-услуг с советами), не новостной блог — как того требуют white-page правила. Если тема лицензируемая — предупредить пользователя и предложить сместить угол (напр. не «клиника», а «студия массажа/эстетики» без мед-заявлений).

## Алгоритм

### Шаг 1. Вытянуть оси уникальности

```bash
cd /home/ubuntu/paperclip/skills/site-prompt
python3 scripts/draw_axes.py "<тема>" 2>&1
```

Скрипт печатает JSON и СРАЗУ пишет fingerprint в журнал (следующий вызов не повторит комбо). Если нужен предпросмотр без записи — добавить `--dry`.

Из JSON взять: `axes` (visual_style, layout_archetype, hero_type, palette, font_pairing, brand_personality, business_model, copy_tone, nav_pattern, motion_signature), `section_order` (секции главной по порядку), `nonce`.

> Ошибка скрипта (пустой банк / нет python) → показать вывод, не выдумывать оси руками.

### Шаг 2. Прочитать гайд и развернуть оси в промпт

Прочитать `references/writing-guide.md` — там точная структура выходного промпта и как каждую ось превратить в конкретное ТЗ. Следовать ей.

Развернуть оси в **живой, конкретный, неповторимый** промпт:

- придумать конкретную компанию под тему (название в стиле `brand_personality`, легенда, что продаёт/как зарабатывает из `business_model`);
- визуальный язык из visual_style + palette + font_pairing + motion_signature (конкретные роли цветов, шрифты, настроение, направление фото);
- структура из layout_archetype + nav_pattern + набор из 5-7+ страниц (постоянные + 2-4 уникальные под нишу, набор меняется от промпта к промпту);
- главная — секции строго в порядке `section_order`, по каждой развёрнутое ТЗ (заголовок-заготовка + содержание);
- тон текстов из copy_tone + примеры формулировок;
- картинки — grok-imagine под контекст;
- компактный технический/compliance-хвост (PHP-only, уникальные классы, без эмодзи/комментов, mobile/SEO/Schema, GDPR Consent Mode v2, Trust/NAP, детект placeholder-телефонов).

**Не сводить к шаблону под нишу.** Оси уже уникальны — усиль это разной идеей/названием/набором страниц. Писать на языке пользователя (по умолчанию русский).

### Шаг 3. Выдать промпт + сохранить файл

1. Вывести готовый промпт пользователю прямо в чат.
2. Сохранить как md-файл (durable-деливери, предпочтение Mike):

```bash
WS="<workspace или yp>"
OUT="/home/ubuntu/arb/$WS/site-prompts"
mkdir -p "$OUT"
SLUG="<короткий-слаг-темы>"
FILE="$OUT/${SLUG}-$(date +%d%m-%H%M).md"
```

Записать промпт в `$FILE` через Write. Сообщить путь. Если пользователь просит доступную ссылку — предложить копию в `/home/ubuntu/TMX/uploads/` (учитывая, что uploads за логин-стеной tmx.moar.tools).

### Шаг 4. Краткий отчёт

```
SITE-PROMPT: готово

Тема: <тема>
Комбо (sig): <sig> — уникальная, в журнал записана
Стиль: <visual_style> | Раскладка: <layout_archetype> | Бренд: <brand_personality>
Секций на главной: <N>  |  Страниц: <M>

Файл: <путь к md>
```

## Как устроена уникальность (для понимания)

- `banks.yaml` — банки: ~28 визуальных стилей × ~18 раскладок × ~20 типов героя × ~28 палитр × ~22 шрифт-пары × ~20 характеров бренда × ~24 бизнес-модели × ~16 тонов × навигация × анимации, плюс из ~40 секций выбирается уникальный поднабор 7-11 в случайном порядке. Пространство комбинаций огромно — практически не повторяется.
- `draw_axes.py` — seed из `/dev/urandom`; cooldown (последние N значений каждой оси не берутся снова); для той же темы избегаются недавние значения; полная комбинация (тема+стиль+раскладка+герой+палитра+бизнес-модель+набор секций) хэшируется и проверяется по журналу — повтор перебрасывается.
- `.history/fingerprints.jsonl` — журнал выданных комбинаций (растёт, чистить не нужно).

Банки можно расширять — добавляй значения в `banks.yaml` тем же форматом, пространство растёт.
